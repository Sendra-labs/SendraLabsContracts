                   PROTOCOLSTORAGE.SOL - FLUJO COMPLETO
═══════════════════════════════════════════════════════════════════════════════

DESCRIPCIÓN:
  - Capa de almacenamiento centralizada del protocolo
  - Gestiona datos de usuarios, posiciones y estadísticas globales
  - Solo accesible por contratos autorizados del protocolo

DEPENDENCIAS:
  - Roles (autenticación de contratos)
  - ProtocolLib (estructuras de datos)

PROTECCIÓN:
  - Modifier onlyProtocol en todas las funciones de escritura
  - Solo contratos aprobados por admins pueden modificar datos

═══════════════════════════════════════════════════════════════════════════════
                     ESTRUCTURAS DE DATOS PRINCIPALES
═══════════════════════════════════════════════════════════════════════════════

1. USUARIO (User):
   │
   ├─ id: uint256                      // ID único del usuario
   ├─ globalPnl: int256                // PnL acumulado (positivo/negativo)
   ├─ globalPosition: GlobalPosition   // Info de posiciones activas
   ├─ transactionCount: uint256        // Total de transacciones
   └─ userData: bytes[]                // Datos custom opcionales

2. POSICIÓN GLOBAL (GlobalPosition):
   │
   ├─ totalPositions: uint256          // Total de posiciones (cerradas + activas)
   ├─ activePositions: uint256         // Solo posiciones activas
   └─ positions: Position[]            // Array de posiciones activas

3. POSICIÓN (Position):
   │
   ├─ positionType: uint128            // Tipo (0=MarketNeutral, etc)
   ├─ id: uint256                      // ID único de la posición
   ├─ pnl: int256                      // PnL de esta posición
   └─ positionData: bytes[]            // Datos específicos del tipo

4. ESTADÍSTICAS DEL PROTOCOLO (ProtocolStats):
   │
   ├─ totalUsers: uint256              // Usuarios registrados
   ├─ totalVolume: uint256             // Volumen total procesado
   ├─ totalPnl: int256                 // PnL global del protocolo
   ├─ totalTransactions: uint256       // Total de transacciones
   ├─ totalPositions: uint256          // Total de posiciones (todas)
   ├─ totalActivePositions: uint256    // Posiciones activas actualmente
   └─ totalValueLocked: uint256        // TVL del protocolo


═══════════════════════════════════════════════════════════════════════════════
                     FLUJO: CREAR/ACTUALIZAR USUARIO
═══════════════════════════════════════════════════════════════════════════════

Main/Protocol → updateUserGlobalPosition(user, newGlobalPosition)
  │
  ├─ VALIDACIÓN: onlyProtocol
  │   │
  │   └─ Roles.isProtocolContract(msg.sender)
  │       ├─ SI TRUE: ✓ Continúa
  │       └─ SI FALSE: ✗ REVERT "InvalidProtocol"
  │
  ├─ PASO 1: Obtener usuario actual
  │   │
  │   └─ User memory updatedUser = users[user]
  │
  ├─ PASO 2: Actualizar GlobalPosition
  │   │
  │   └─ updatedUser.globalPosition = newGlobalPosition
  │
  └─ PASO 3: Guardar usuario (llama updateUser interno)
      │
      └─ updateUser(user, updatedUser)
          │
          ├─ SI !isUser(user):
          │   │
          │   └─ createUser(user)
          │       │
          │       ├─ protocolStats.totalUsers++
          │       │
          │       └─ users[user] = User(
          │               id: totalUsers,
          │               globalPnl: 0,
          │               globalPosition: empty,
          │               transactionCount: 0,
          │               userData: []
          │           )
          │
          └─ users[user] = updatedUser


EJEMPLO COMPLETO (Abrir Market Neutral):

  Main.openMarketNeutral()
    │
    └─ Main.updatePositions(newPositionData, 0)
        │
        ├─ updateUserTransactionCount(user, 1)
        │   └─ user.transactionCount += 1
        │
        ├─ getUser(user) → userData
        │
        ├─ positionId = userData.totalPositions + 1
        │
        ├─ newPosition = createPosition(...)
        │
        └─ updateUserGlobalPosition(
                user,
                GlobalPosition(
                    totalPositions: positionId,
                    activePositions: activePositions + 1,
                    positions: [...oldPositions, newPosition]
                )
            )
            │
            └─ ProtocolStorage guarda los cambios


═══════════════════════════════════════════════════════════════════════════════
                     FLUJO: ACTUALIZAR PNL DEL USUARIO
═══════════════════════════════════════════════════════════════════════════════

Protocol → updateUserGlobalPnl(user, pnlChange)
  │
  ├─ VALIDACIÓN: onlyProtocol
  │
  ├─ PASO 1: Obtener usuario
  │   │
  │   └─ User memory updatedUser = users[user]
  │
  ├─ PASO 2: Actualizar PnL
  │   │
  │   └─ updatedUser.globalPnl += pnlChange
  │       │
  │       ├─ Si pnlChange = +1000 → globalPnl aumenta
  │       └─ Si pnlChange = -500 → globalPnl disminuye
  │
  └─ PASO 3: Guardar usuario
      │
      └─ updateUser(user, updatedUser)


EJEMPLO (Cerrar posición con profit):

  Posición abierta con 1 ETH
  Cerrada con 1.2 ETH
  Profit = 0.2 ETH = +200,000,000,000,000,000 wei
  
  updateUserGlobalPnl(user, +200000000000000000)
    └─ user.globalPnl aumenta 0.2 ETH


═══════════════════════════════════════════════════════════════════════════════
                     FLUJO: ACTUALIZAR ESTADÍSTICAS GLOBALES
═══════════════════════════════════════════════════════════════════════════════

Múltiples funciones para actualizar stats del protocolo:

1. updateTotalVolume(amount)
   │
   └─ protocolStats.totalVolume += amount

2. updateTotalPnl(pnl)
   │
   └─ protocolStats.totalPnl += pnl

3. updateTotalTransactions()
   │
   └─ protocolStats.totalTransactions++

4. updateTotalPositions()
   │
   └─ protocolStats.totalPositions++

5. updateTotalActivePositions(change)
   │
   ├─ SI change > 0:
   │   └─ protocolStats.totalActivePositions += change
   │
   └─ SI change < 0:
       └─ protocolStats.totalActivePositions -= abs(change)
           (con protección contra underflow)

6. updateTotalValueLocked(change)
   │
   ├─ SI change > 0:
   │   └─ protocolStats.totalValueLocked += change
   │
   └─ SI change < 0:
       └─ protocolStats.totalValueLocked -= abs(change)
           (con protección contra underflow)


EJEMPLO (Usuario abre Market Neutral con 2 ETH):

  updateTotalVolume(2 ETH)
  updateTotalTransactions()
  updateTotalPositions()
  updateTotalActivePositions(+1)
  updateTotalValueLocked(+2 ETH)


EJEMPLO (Usuario cierra con profit de 0.5 ETH):

  updateTotalPnl(+0.5 ETH)
  updateTotalActivePositions(-1)
  updateTotalValueLocked(-2.5 ETH)  // Sale capital + profit

Cualquiera puede leer (no requieren onlyProtocol):

1. getUser(address) → User
   │
   └─ Retorna todos los datos del usuario
       ├─ ID
       ├─ GlobalPnl

       ├─ TransactionCount

   │
   └─ Verifica si el usuario existe (id != 0)

3. getUsersCount() → uint256
   │
   └─ Retorna total de usuarios registrados

4. getProtocolStats() → ProtocolStats
   │
   └─ Retorna todas las estadísticas del protocolo
       ├─ TotalUsers
       ├─ TotalVolume
       ├─ TotalPnl
       ├─ TotalTransactions
       ├─ TotalPositions
       ├─ TotalActivePositions
       └─ TotalValueLocked


═══════════════════════════════════════════════════════════════════════════════
                     DIAGRAMA: CICLO DE VIDA DE USUARIO
═══════════════════════════════════════════════════════════════════════════════

Usuario nuevo interactúa por primera vez:
  │
  ├─ Main.openMarketNeutral() llamado
  │   │
  │   └─ ProtocolStorage.updateUserGlobalPosition()
  │       │
  │       └─ isUser(user) → FALSE
  │           │
  │           └─ createUser(user)
  │               │
  │               ├─ totalUsers++ (ej: 1 → 2)
  │               │
  │               └─ users[user] = User(
  │                       id: 2,
  │                       globalPnl: 0,
  │                       globalPosition: vacio,
  │                       transactionCount: 0,
  │                       userData: []
  │                   )
  │
  ├─ Usuario ahora existe en el sistema
  │
  ├─ Futuras operaciones:
  │   │
  │   ├─ isUser(user) → TRUE
  │   └─ Se actualiza el usuario existente
  │
  └─ Usuario puede:
      ├─ Abrir múltiples posiciones
      ├─ Cerrar posiciones
      ├─ Acumular PnL
      └─ Consultar su historial


═══════════════════════════════════════════════════════════════════════════════
                     PROTECCIÓN CONTRA UNDERFLOW
═══════════════════════════════════════════════════════════════════════════════

updateTotalActivePositions(int256 change):
  
  SI change = -5 PERO totalActivePositions = 3:
    │
    ├─ decrease = 5
    ├─ totalActivePositions = 3
    │
    └─ SI totalActivePositions >= decrease:
       │   └─ totalActivePositions -= decrease
       │
       └─ SINO:
           └─ totalActivePositions = 0  ← PROTECCIÓN


updateTotalValueLocked(int256 change):
  
  Misma lógica que activePositions
  Previene underflow y valores negativos


═══════════════════════════════════════════════════════════════════════════════
                     MAPPING DE USUARIOS
═══════════════════════════════════════════════════════════════════════════════

mapping(address => User) public users

Estructura:
  
  0x123...abc → User(
                    id: 1,
                    globalPnl: +500000000000000000,  // +0.5 ETH
                    globalPosition: GlobalPosition(
                        totalPositions: 5,
                        activePositions: 2,
                        positions: [
                            Position(
                                type: 0,
                                id: 3,
                                pnl: +200000000000000000,
                                data: [...]
                            ),
                            Position(
                                type: 0,
                                id: 5,
                                pnl: 0,
                                data: [...]
                            )
                        ]
                    ),
                    transactionCount: 10,
                    userData: []
                )


Acceso rápido por address:
  
  Frontend → getUser(0x123...abc)
  Backend → getUser(0x123...abc)
  Contrato → getUser(msg.sender)

                     VENTAJAS DEL DISEÑO
═══════════════════════════════════════════════════════════════════════════════

✓ CENTRALIZADO: Un solo lugar para todos los datos del protocolo
✓ SEGURO: Solo contratos autorizados pueden escribir
✓ FLEXIBLE: userData permite campos custom sin redeploy

✓ PROTEGIDO: Underflow protection en decrementos
✓ ESCALABLE: Fácil añadir nuevas estadísticas
✓ AUDITABLE: Todas las estadísticas en un lugar
