═══════════════════════════════════════════════════════════════════════════════
                      BUNDLESROUTER.SOL - FLUJO COMPLETO
═══════════════════════════════════════════════════════════════════════════════

DESCRIPCIÓN:
  - Router central que dirige operaciones a diferentes bundles/executors
  - Sistema de permisos para contratos autorizados del protocolo
  - Maneja el forwarding de ETH a los ejecutores

DEPENDENCIAS:
  - Roles (sistema de autenticación)
  - ReentrancyGuard (protección contra ataques)

═══════════════════════════════════════════════════════════════════════════════
                         FUNCIÓN PRINCIPAL: ROUTE
═══════════════════════════════════════════════════════════════════════════════

Main/ProtocolContract → route(
                          _bundle,      // Address del executor (ej: MarketNeutral)
                          functionId,   // ID de función a ejecutar
                          _data         // bytes[] con parámetros
                        ) [payable]
  │
  ├─ VALIDACIÓN 1: onlyProtocol
  │   │
  │   └─ Roles.isProtocolContract(msg.sender)
  │       │
  │       ├─ SI TRUE: ✓ Continúa
  │       └─ SI FALSE: ✗ REVERT "SenderNotAllowed"
  │
  ├─ VALIDACIÓN 2: nonReentrant
  │   │
  │   └─ ReentrancyGuard establece lock
  │       │
  │       ├─ SI no hay lock activo: ✓ Continúa
  │       └─ SI hay lock activo: ✗ REVERT (previene reentrada)
  │
  ├─ PASO 1: Construir llamada dinámica
  │   │
  │   └─ abi.encodeWithSelector(
  │           bytes4(keccak256("execute(uint8,bytes[])")),
  │           functionId,
  │           _data
  │       )
  │       │
  │       └─ Crea calldata para execute() del bundle
  │
  ├─ PASO 2: Llamada de bajo nivel con ETH
  │   │
  │   └─ _bundle.call{value: msg.value}(calldata)
  │       │
  │       ├─ Envía msg.value completo al bundle
  │       │
  │       ├─ Ejecuta execute(functionId, _data) en el bundle
  │       │   │
  │       │   └─ Ejemplo para MarketNeutral:
  │       │       │
  │       │       ├─ functionId = 0 → openPositionWithEther()
  │       │       └─ functionId = 1 → closePositionV2()
  │       │
  │       └─ Retorna (bool success, bytes returnData)
  │
  └─ PASO 3: Validar resultado
      │
      ├─ SI success == true: ✓ Operación exitosa
      └─ SI success == false: ✗ REVERT "ExecutionFailed"

═══════════════════════════════════════════════════════════════════════════════
                         CONTROL DE ACCESO (Roles)
═══════════════════════════════════════════════════════════════════════════════

CONTRATOS AUTORIZADOS:
  
  Para que un contrato pueda usar BundlesRouter.route():
  
  1. Admin debe llamar Roles.allowContract(contractAddress, name)
     │
     ├─ Primer admin aprueba: approvals = 1
     └─ Segundo admin aprueba: approvals = 2 → CONTRACT ACTIVADO
  
  2. Roles.isProtocolContract(contractAddress) → true
  
  3. Ahora ese contrato puede llamar BundlesRouter.route()


EJEMPLO DE SETUP:

  Admin1 → Roles.allowContract(Main, "Main")
  Admin2 → Roles.allowContract(Main, "Main")
           └─ Main ahora está autorizado ✓
  
  Main → BundlesRouter.route(...) 
         └─ ✓ Permitido


═══════════════════════════════════════════════════════════════════════════════
                      GESTIÓN DE ETH (msg.value)
═══════════════════════════════════════════════════════════════════════════════

IMPORTANTE: BundlesRouter NO retiene ETH, solo lo forwarded

Usuario envía 1 ETH:
  │
  ├─ Main recibe: 1 ETH
  │   │
  │   └─ Divide en 2 (para 2 órdenes): 0.5 ETH cada una
  │       │
  │       ├─ Main → BundlesRouter.route{value: 0.5 ETH}(...)
  │       │   │
  │       │   └─ BundlesRouter → MarketNeutral{value: 0.5 ETH}
  │       │       │
  │       │       └─ MarketNeutral → GMX ExchangeRouter{value: 0.5 ETH}
  │       │
  │       └─ Main → BundlesRouter.route{value: 0.5 ETH}(...)
  │           │
  │           └─ [mismo flujo]


Balance en cada paso:
  
  Usuario:        -1.0 ETH
  Main:            0.0 ETH (forward inmediato)
  BundlesRouter:   0.0 ETH (forward inmediato)
  MarketNeutral:   0.0 ETH (forward a GMX)
  GMX:            +1.0 ETH (final destination)


═══════════════════════════════════════════════════════════════════════════════
                         ERRORES Y MANEJO
═══════════════════════════════════════════════════════════════════════════════

ERROR: SenderNotAllowed
  - Causa: Contrato no autorizado intenta usar route()
  - Solución: Admin debe aprobar contrato vía Roles.allowContract()

ERROR: ExecutionFailed
  - Causa: La llamada al bundle falló
  - Posibles razones:
    * Bundle no tiene función execute()
    * Parámetros incorrectos
    * Revert en lógica del bundle
    * Falta de gas
    * Bundle pausado o con error

ERROR: Reentrancy
  - Causa: Intento de llamada reentrante
  - Protección: ReentrancyGuard bloquea automáticamente

═══════════════════════════════════════════════════════════════════════════════
                              CÓDIGO CLAVE
═══════════════════════════════════════════════════════════════════════════════

Llamada de bajo nivel:
  
  (bool success,) = _bundle.call{value: msg.value}(
      abi.encodeWithSelector(
          bytes4(keccak256("execute(uint8,bytes[])")),
          functionId,
          _data
      )
  );
  
  ¿Por qué bajo nivel?
  - Permite llamar a diferentes contratos sin conocer su interfaz
  - Dinámico: functionId determina qué función ejecutar
  - Flexible: _data puede contener cualquier estructura
