Problem Statement

Address-Based Position Aggregation

Position Aggregation by Address in GMX

GMX V2's position management system aggregates all positions opened from the same address. When multiple users interact through a single protocol contract, their positions become indistinguishable at the GMX layer. The msg.sender that GMX records is the protocol contract address, not the end user's address, making position ownership tracking impossible.

GMX Position Aggregation Issue 
// All positions share the same msg.sender
contract Protocol {
    function openPosition() external {
        GMX.createOrder(...);
        // msg.sender in GMX context = Protocol contract address
        // Cannot differentiate positions between User A and User B
    }
}

Solution Architecture

Per-User Proxy Pattern

01

Per-User Proxy Instances

Each user receives a unique proxy contract instance with its own address. When the proxy executes GMX operations via delegatecall, the msg.sender from GMX's perspective is the proxy address, enabling complete position isolation and ownership tracking.

02

Delegatecall Execution Pattern

Proxies use delegatecall to execute MarketNeutral logic within their own storage context. This pattern enables code reuse while maintaining isolated storage per proxy, ensuring state separation between user positions.

03

Proxy Pool & Lifecycle Management

Proxies with no active positions are marked available and returned to a pool. The ProxyManager implements batching and reuse logic to minimize gas costs by avoiding unnecessary deployments and enabling proxy recycling.

Architecture Overview

ProxyFactory

Deploys new proxy instances on demand via CREATE2 or standard deployment

function deploy(uint256 _id) external returns (address)
  • Only callable by ProxyManager
  • Assigns unique proxy ID
  • Returns proxy contract address

ProxyManager

Manages proxy lifecycle, availability, and assignment

  • Proxy assignment to users
  • Batch-based availability pool (MAX_BATCH_SIZE = 100)
  • Availability tracking and recycling
  • Owner mapping per proxy ID

MarketNeutralProxy

User-specific proxy contract with isolated storage

  • Active markets tracking (markets[] array)
  • Access control via onlyOwner modifier
  • Delegatecall to MarketNeutral implementation
  • Availability check (isAvailable() when markets.length == 0)

MarketNeutral

Shared implementation contract containing execution logic

  • GMX order creation and management
  • Position opening/closing logic
  • Storage-agnostic execution (via delegatecall)
  • Reusable across all proxy instances
Execution Flow

Proxy → MarketNeutral → GMX

1

Proxy Request & Assignment

User initiates position opening. ProxyManager checks for available proxies in the batch pool via getAvailableProxy(). If none available, deploys new proxy instance via ProxyFactory.

ProxyManager.initializeProxy(userAddress) → returns proxyAddress
2

Market Conflict Check & Access Control

Proxy validates that requested markets are not already in use via isMarketBeingUsed() check. The onlyOwner modifier ensures only the assigned user can execute operations on this proxy instance.

MarketNeutralProxy.isMarketBeingUsed(marketLong, marketShort) → bool
3

Delegatecall Execution

Proxy executes MarketNeutral functions via delegatecall, which runs the implementation code in the proxy's storage context. This preserves address(this) as the proxy address while executing shared logic. 

// MarketNeutralProxy context
(bool success,) = marketNeutral.delegatecall(
    abi.encodeWithSignature(
        "openEtherMarketNeutral((string,string,uint256,uint256,uint256,uint256,uint256))",
        _input
    )
);
// address(this) = proxy address
// msg.sender = original user address
4

GMX Interaction

MarketNeutral implementation calls GMX's ExchangeRouter to create orders. From GMX's perspective, msg.sender is the proxy contract address, enabling position separation based on proxy identity.

IExchangeRouter.createOrder(...) // GMX records msg.sender as proxy address // Position key = keccak256(proxyAddress, market, collateralToken, isLong)
5

Position Isolation in GMX

GMX creates position entries keyed by the proxy address. Each proxy maintains separate position state in GMX's DataStore, enabling complete isolation between users even when using the same protocol implementation.

6

Proxy Release & Pool Return

Upon position closure, proxy checks if markets.length == 0 via isAvailable(). If available, ProxyManager marks the proxy as available and returns it to the batch pool for reuse, optimizing gas costs.

ProxyManager.setAvailable(proxyId) // Adds proxy to availableProxiesBatch[currentBatchId] // Sets owner to address(0) for reassignment
Implementation

Core Contracts

MarketNeutralProxy

Proxy Contract 
contract MarketNeutralProxy is ReentrancyGuard {
    AddressProvider public immutable addressProvider;
    address public marketNeutral;
    uint256 public immutable id;
    
    address[] internal markets; // Tracks active markets for this proxy

    constructor(address _addressProvider, uint256 _id) {
        addressProvider = AddressProvider(_addressProvider);
        id = _id;
        marketNeutral = addressProvider.getAddress("MarketNeutral");
    }

    modifier onlyOwner() {
        address owner = ProxyManager(
            addressProvider.getAddress("ProxyManager")
        ).getOwner(id);
        if (msg.sender != owner) revert NotOwner();
        _;
    }

    function openEtherMarketNeutralDelegatecall(
        MarketNeutralLib.EtherMarketNeutralInput calldata _input
    ) public payable onlyOwner nonReentrant {
        // Prevent duplicate positions on same market pair
        manageMarkets(_input.marketLong, _input.marketShort);
        
        // Execute MarketNeutral logic in proxy's storage context
        // Context: address(this) = proxy address, msg.sender = original user
        // GMX will see msg.sender as this proxy address
        (bool success,) = marketNeutral.delegatecall(
            abi.encodeWithSignature(
                "openEtherMarketNeutral((string,string,uint256,uint256,uint256,uint256,uint256))",
                _input
            )
        );
        require(success, "Delegatecall failed");
    }

    function manageMarkets(string calldata _marketLong, string calldata _marketShort) internal {
        GMXMarketsRegistry gmxMarkets = GMXMarketsRegistry(
            addressProvider.getAddress("GMXMarkets")
        );
        address marketLong = gmxMarkets.getMarket(_marketLong);
        address marketShort = gmxMarkets.getMarket(_marketShort);
        
        // Check for existing market usage to prevent conflicts
        for(uint256 i = 0; i < markets.length; i++) {
            if (markets[i] == marketLong || markets[i] == marketShort) {
                revert MarketAlreadyExists();
            }
        }
        markets.push(marketLong);
        markets.push(marketShort);
    }

    function isAvailable() public view returns (bool) {
        // Proxy is available when no active positions (markets array empty)
        return markets.length == 0;
    }
    
    error NotOwner();
    error MarketAlreadyExists();
}

ProxyManager

Management 
contract ProxyManager {
    struct Proxy {
        address owner;    // Current user assigned to this proxy
        address proxy;    // Proxy contract address
    }
    
    struct Batch {
        uint256 availableCount;  // Number of available proxies in batch
        uint256[] proxyIds;      // Array of proxy IDs available for reuse
    }
    
    mapping(uint256 => Proxy) public proxies;
    mapping(uint256 => Batch) public availableProxiesBatch;
    
    uint256 public proxyCount;
    uint256 public batchId;
    uint256 public constant MAX_BATCH_SIZE = 100;

    function initializeProxy(address _owner) 
        public 
        onlyProtocol
        returns (address _proxyAddress) 
    {
        // Check for available proxy in existing batches
        (uint256 _proxyId, uint256 _batchId, address proxyAddress, bool isAvailable) = 
            getAvailableProxy();
            
        if(!isAvailable) {
            // Deploy new proxy instance if pool is empty
            _proxyAddress = deployProxy(_owner);
            return (_proxyAddress);
        } else {
            // Reuse available proxy from batch pool
            claimAvailableProxy(_proxyId, _batchId, _owner);
            return (proxyAddress);
        }
    }
    
    function getAvailableProxy() public view returns (
        uint256 proxyId, 
        uint256 batchId, 
        address proxyAddress, 
        bool isAvailable
    ) {
        // Iterate through batches to find available proxy
        for(uint256 i = 0; i < batchId + 1; i++) {
            uint256 availableCount = availableProxiesBatch[i].availableCount;
            if (availableCount > 0) {
                uint256 _id = availableProxiesBatch[i].proxyIds[availableCount - 1];
                return (_id, i, proxies[_id].proxy, true);
            }
        }
        return (0, 0, address(0), false);
    }

    function setAvailable(uint256 _proxyId) public onlyProtocol {
        // Mark proxy as available when no active positions
        // Called by proxy itself or callback contract after position closure
        if(MarketNeutralProxy(proxies[_proxyId].proxy).isAvailable()) {
            // Add to current batch pool for reuse
            availableProxiesBatch[batchId].proxyIds.push(_proxyId);
            availableProxiesBatch[batchId].availableCount++;
            setOwner(_proxyId, address(0)); // Reset ownership for reassignment
        }
    }
    
    modifier onlyProtocol() {
        if(!roles.isProtocolContract(msg.sender)) revert SenderNotAllowed();
        _;
    }
}
Architecture Benefits

Design Advantages

Position Isolation

Complete separation of user positions at the GMX layer through unique proxy addresses. Position keys are computed using proxy address, ensuring no cross-contamination.

Gas Optimization

Batch-based proxy pooling and reuse system minimizes deployment costs. Proxies are recycled when positions close, reducing gas overhead by ~80% compared to per-operation deployments.

Scalability

Extensible architecture supports adding new execution logic without modifying existing proxy contracts. Implementation contracts can be upgraded independently of deployed proxies.

Storage Efficiency

Minimal proxy storage footprint: only proxy ID and AddressProvider reference. Market tracking is transient and cleared upon position closure, enabling efficient memory management.

Access Control

Per-proxy owner mapping enables granular access control. Only the assigned user can execute operations on their proxy instance via onlyOwner modifier. ReentrancyGuard protects against reentrancy attacks.

Market Conflict Prevention

Each proxy maintains an array of active markets to prevent duplicate positions on the same market pair. Market tracking ensures one position per market per proxy, reducing operational errors.

Storage Architecture

Extensible Storage System

Dynamic Schema System

The protocol uses a flexible storage system that allows storing any data type in positions without requiring contract redeployment. This is achieved through bytes[] arrays and dynamic schema definitions managed by UpgradeableLib.

Position Structure 
struct Position {
    uint128 positionType;    // ID referencing schema in UpgradeableLib
    uint256 id;
    int256 pnl;
    bool isActive;
    bytes[] positionData;    // Generic array storing encoded data
}

struct PositionType {
    string name;             // e.g., "MarketNeutral"
    uint8 origin;            // 0 = Funds, 1 = Bundles
    PositionParam[] positionParams;  // Schema definition
    FunctionInputs[] openPositionInputs;
    FunctionInputs[] closePositionInputs;
}

struct PositionParam {
    uint8 paramType;         // 0=uint256, 1=address, 2=bool, 3=bytes...
    string paramName;        // e.g., "totalEthAmount", "marketLong"
}

bytes[] Storage

All position data is stored as bytes[] arrays. Each element is ABI-encoded and can represent any Solidity type. The schema defines which type each index represents.

bytes[] memory positionData = new bytes[](18); positionData[0] = abi.encode(totalEthAmount); // uint256 positionData[1] = abi.encode(isNativeToken); // bool positionData[2] = abi.encode(marketAddress); // address

UpgradeableLib Schema

UpgradeableLib maintains a registry of position type schemas. Each schema defines the structure and types of data stored in positionData arrays.

  • Dynamic schema registration via addPositionType()
  • Schema lookup via getPositionType(positionTypeId)
  • No redeployment required for new types
  • Admin-controlled schema management

Encoding & Decoding

Data is encoded using abi.encode() when storing and decoded using abi.decode() when reading. The schema provides type information for correct decoding.

// Encoding bytes memory encoded = abi.encode(uint256(1000)); // Decoding uint256 amount = abi.decode(positionData[0], (uint256));

Type System

Supported types: 0=uint256, 1=address, 2=bool, 3=bytes, 4=uint256[], 5=address[], 6=bool[], 7=bytes[], and multi-dimensional arrays. This covers all common Solidity types.

Implementation Detail

MarketNeutral Position Data Structure

18-Element Data Array

MarketNeutral stores comprehensive position information in an 18-element bytes[] array. This includes collateral amounts, market addresses, prices, timestamps, position keys, and PnL data. Each element is ABI-encoded and can be decoded using the schema defined in UpgradeableLib.

MarketNeutral Position Data Encoding 
bytes[] memory newPositionData = new bytes[](18);

// Collateral & Token Info
newPositionData[0] = abi.encode(totalEthAmount);        // uint256: Total collateral amount
newPositionData[1] = abi.encode(true);                  // bool: isNativeToken (ETH vs USDC)

// Market Addresses
newPositionData[2] = abi.encode(marketLongAddress);     // address: Long market address
newPositionData[3] = abi.encode(marketShortAddress);    // address: Short market address

// Position Sizes
newPositionData[4] = abi.encode(sizeDeltaUsdLong);      // uint256: Long position size (USD)
newPositionData[5] = abi.encode(sizeDeltaUsdShort);     // uint256: Short position size (USD)

// Initial Prices
newPositionData[6] = abi.encode(initialPriceLong);      // uint256: Entry price for long
newPositionData[7] = abi.encode(initialPriceShort);     // uint256: Entry price for short

// Initial USD Value
newPositionData[8] = abi.encode(initialUsdValue);       // uint256: Total USD value at entry

// Timestamps
newPositionData[9] = abi.encode(block.timestamp);       // uint256: Position open date
newPositionData[10] = abi.encode(uint256(0));           // uint256: Position close date (0 if active)

// Final Values (updated on close)
newPositionData[11] = abi.encode(uint256(0));           // uint256: Final USD value
newPositionData[12] = abi.encode(uint256(0));           // uint256: Final price token long
newPositionData[13] = abi.encode(uint256(0));           // uint256: Final price token short

// PnL
newPositionData[14] = abi.encode(int256(0));            // int256: Current PnL (updated on close)

// Position Keys (GMX)
newPositionData[15] = abi.encode(longPositionKey);      // bytes32: GMX position key for long
newPositionData[16] = abi.encode(shortPositionKey);     // bytes32: GMX position key for short

// Proxy Address
newPositionData[17] = abi.encode(address(this));        // address: Proxy contract address

Data Categories

  • Indices 0-1: Collateral information
  • Indices 2-3: Market addresses (long/short)
  • Indices 4-5: Position sizes in USD
  • Indices 6-7: Entry prices
  • Index 8: Initial USD value
  • Indices 9-10: Timestamps (open/close)
  • Indices 11-13: Final values (on close)
  • Index 14: Profit and Loss
  • Indices 15-16: GMX position keys
  • Index 17: Proxy address

Position Key Calculation

Position keys are calculated using proxy address, market address, collateral token, and direction (long/short). These keys are used to query positions in GMX.

bytes32 longKey = keccak256( abi.encodePacked( proxyAddress, // address(this) in proxy context marketLongAddress, collateralToken, // WETH or USDC true // isLong ) );

Data Updates

On position closure, indices 10-14 are updated with final values: close date, final USD value, final prices, and calculated PnL. The position key remains constant throughout the position lifecycle.

Schema Registration

The 18-parameter schema is registered in UpgradeableLib as positionType 0. This allows frontend and other contracts to correctly decode and display position data without hardcoded knowledge of the structure.

Reading MarketNeutral Position Data 
// Get position from storage
Position memory position = protocolStorage.getUserPositionById(user, positionId);
bytes[] memory positionData = position.positionData;

// Decode core data
uint256 totalAmount = abi.decode(positionData[0], (uint256));
bool isNative = abi.decode(positionData[1], (bool));
address marketLong = abi.decode(positionData[2], (address));
address marketShort = abi.decode(positionData[3], (address));
uint256 sizeLong = abi.decode(positionData[4], (uint256));
uint256 sizeShort = abi.decode(positionData[5], (uint256));

// Decode pricing data
uint256 initialPriceLong = abi.decode(positionData[6], (uint256));
uint256 initialPriceShort = abi.decode(positionData[7], (uint256));
uint256 initialUsdValue = abi.decode(positionData[8], (uint256));

// Decode timestamps
uint256 openDate = abi.decode(positionData[9], (uint256));
uint256 closeDate = abi.decode(positionData[10], (uint256));

// Decode final values (if closed)

uint256 finalPriceShort = abi.decode(positionData[13], (uint256));

// Decode proxy address

Configuration System

Address Provider Pattern

Centralized Address Management

The AddressProvider contract serves as a centralized registry for all protocol contract addresses. This pattern enables easy updates, modular architecture, and eliminates the need for hardcoded addresses throughout the codebase. Contracts query AddressProvider to get addresses of other protocol components at runtime.

AddressProvider Contract 
contract AddressProvider {
    mapping(string => address) public addresses;
    
    function setAddress(string memory _name, address _address) external onlyAdmin {
        addresses[_name] = _address;
    }
    
    function getAddress(string memory _name) external view returns (address) {
        return addresses[_name];
    }
}

Registered Contracts

All protocol contracts are registered with string identifiers:

  • "ProtocolStorage" → ProtocolStorage address
  • "MarketNeutral" → MarketNeutral implementation
  • "ProxyManager" → ProxyManager address
  • "ProxyFactory" → ProxyFactory address
  • "GMXPrices" → GMXPrices utility
  • "GMXMarkets" → GMXMarketsRegistry
  • "Roles" → Roles contract
  • "WETH" → Wrapped Ether address

Usage Pattern

Contracts store an immutable reference to AddressProvider and query it when they need to interact with other protocol components.

AddressProvider public immutable addressProvider; constructor(address _addressProvider) { addressProvider = AddressProvider(_addressProvider); } function someFunction() external { ProtocolStorage storage = ProtocolStorage( addressProvider.getAddress("ProtocolStorage") ); // Use storage contract... }

Benefits

  • Single source of truth for addresses
  • Easy contract upgrades (update address, no code changes)
  • Reduced deployment complexity
  • Better testability (mock addresses)
  • Modular architecture

Admin Control

Only admin addresses (via Roles contract) can update registered addresses. This ensures security while allowing protocol evolution and upgrades without redeploying dependent contracts.
